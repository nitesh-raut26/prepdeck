## The ask

Book meetings with a start and end time across a set of rooms: reject overlaps in the same
room, assign a free room when one's available, and answer "how many rooms do we need?"
(This is **My Calendar I/II** and **Meeting Rooms II / LeetCode 253** as a design problem.)

<Callout type="info" title="Why this one, and at what level">
It rewards knowing the **interval toolkit** ([heaps & intervals](/dsa/heaps-and-intervals))
and wrapping it in clean objects. **SDE-1:** book + conflict detection. **SDE-2:** the
min-rooms sweep-line/heap and a clean Scheduler API. **SDE-3:** recurring events, time
zones, attendee free-slot intersection, and double-booking under concurrency. Asked at
**Google, Microsoft, Amazon, Atlassian** (calendars are their bread and butter).
</Callout>

## The two core algorithms

- **Conflict detection (one room):** two intervals `[s1,e1)` and `[s2,e2)` overlap iff
  `s1 < e2 and s2 < e1`. Keep each room's bookings sorted (a `TreeMap`/balanced BST keyed
  on start) so you can binary-search the neighbours and check only those — O(log n) per
  booking instead of scanning all.
- **Minimum rooms (sweep line + heap):** sort meetings by start; keep a **min-heap of end
  times** of in-progress meetings. For each meeting, if the earliest end ≤ its start, a room
  freed up (pop and reuse); else allocate a new room (push). The heap's max size is the
  answer.

## Implementation

```ts
type Meeting = { start: number; end: number };

class Scheduler {
  // Each room holds bookings sorted by start time.
  private rooms: Meeting[][] = [];

  private overlaps(a: Meeting, b: Meeting) {
    return a.start < b.end && b.start < a.end;   // half-open intervals
  }

  // Book into the first room with no conflict; open a new room if none fits.
  book(m: Meeting): number {
    for (let i = 0; i < this.rooms.length; i++) {
      if (!this.rooms[i].some((b) => this.overlaps(b, m))) {
        this.rooms[i].push(m);
        return i;                                 // assigned room index
      }
    }
    this.rooms.push([m]);                          // all busy → new room
    return this.rooms.length - 1;
  }
}

// Minimum rooms for a fixed set — the sweep-line / min-heap classic.
function minRooms(meetings: Meeting[]): number {
  const sorted = [...meetings].sort((a, b) => a.start - b.start);
  const endHeap: number[] = [];                    // min-heap of end times
  let peak = 0;
  for (const m of sorted) {
    while (endHeap.length && endHeap[0] <= m.start) heapPop(endHeap);
    heapPush(endHeap, m.end);
    peak = Math.max(peak, endHeap.length);
  }
  return peak;
}
```

<Callout type="tip" title="Half-open intervals remove the off-by-one">
Treat times as `[start, end)`. A meeting ending at 10:00 and one starting at 10:00 then
**don't** conflict (`s1 < e2 and s2 < e1` is false), which matches how calendars actually
behave. State the convention up front — it kills a whole class of boundary bugs.
</Callout>

## Complexity & follow-ups

- **Booking:** O(log n) per room with a TreeMap; the naive `some()` scan above is O(n) per
  room — fine to start, then optimize when asked.
- **Min rooms:** O(n log n) via the heap.
- **Recurring meetings:** store a rule (RRULE) + expand lazily into instances within a
  query window — don't materialize infinite occurrences.
- **Time zones:** store everything in **UTC**, convert at the edges; mind DST transitions.
- **Find a common slot** across attendees: merge each person's busy intervals, then
  intersect the free gaps (interval intersection).
- **Concurrency / double-booking:** two requests for the same room+time race — guard with a
  per-room lock or an **optimistic** check-and-insert (unique constraint on room+overlap)
  so the second booking fails cleanly.

<QA q="How do you compute the minimum number of rooms for a set of meetings?">

It's the **maximum number of overlapping meetings** at any instant. Sort meetings by start
time and sweep through them with a **min-heap of end times**: before placing each meeting,
pop every end time `≤` its start (those rooms are now free), then push its end time. The
peak heap size during the sweep is the minimum rooms needed — O(n log n). Equivalent
framing: a sweep line over `+1` at each start and `−1` at each end, tracking the running
peak.

</QA>

<QA q="How do you stop two simultaneous requests from double-booking the same room?">

Make the "check for conflict, then insert" step **atomic**. Either take a **per-room lock**
so only one booking evaluates that room's timeline at a time, or use **optimistic
concurrency** — insert with a database constraint/transaction that rejects overlapping
intervals and have the loser retry. Add an **idempotency key** so a client retry of the
same request doesn't create a duplicate. Without atomicity, both requests can see the slot
free and both insert — the classic race.

</QA>
