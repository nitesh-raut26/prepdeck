## The secret nobody tells beginners

Interviewers aren't testing whether you've memorized 500 solutions. They're
testing whether you can **recognize which of ~15 patterns a new problem is
wearing**, and then apply that pattern calmly. Strong candidates aren't
faster thinkers — they've just learned that *the problem statement itself
names the pattern*, if you know the code words.

This page is that decoder. Pin it.

## The decoder table

Read the problem. The moment one of these phrases appears, you have your
prime suspect:

| The problem says… | Reach for | Why it works |
|---|---|---|
| "sorted array", "find in sorted…" | [Binary search](/dsa/binary-search) | Sorted = you can throw away half per question |
| "minimum X **such that** it works", "max of min" | [Binary search on the answer](/dsa/binary-search) | Feasibility flips once → search the boundary |
| "pair / triplet that sums to…", "compare two ends" | [Two pointers](/dsa/two-pointers) | Each comparison safely moves one pointer inward |
| "longest/shortest **substring** or **subarray** with…" | [Sliding window](/dsa/sliding-window) | Grow/shrink a range instead of re-scanning |
| "have I seen this before?", "count occurrences", "two things match" | [Hash table](/dsa/hash-tables) | Trades memory for instant lookups |
| "next greater element", "matching brackets", "undo", "most recent" | [Stack](/dsa/stacks-and-queues) | Last-in first-out mirrors nesting & recency |
| "process in arrival order", "level by level", "shortest path, equal steps" | [Queue / BFS](/dsa/graphs-bfs-dfs) | First-in first-out explores nearest-first |
| "top k", "k-th largest", "merge k streams", "median of a stream" | [Heap](/dsa/heaps-and-intervals) | Always hands you the current best in O(log n) |
| "**all** subsets / permutations / ways to place…" | [Backtracking](/dsa/backtracking) | Enumerate by choose → explore → un-choose |
| "**how many** ways", "minimum cost to reach", "can it be formed" (+ choices overlap) | [DP](/dsa/dynamic-programming) | Same sub-questions repeat → answer each once, in a table |
| "connected", "islands", "reachable", "depends on" | [Graph BFS/DFS](/dsa/graphs-bfs-dfs) | Relationships = nodes + edges; traverse them |
| "are these in the same group?", "merge groups", "detect cycle while adding edges" | [Union-Find](/dsa/union-find) | Leaders + sticky notes answer 'same group?' instantly |
| "intervals", "meetings", "overlapping ranges" | [Sort + sweep](/dsa/heaps-and-intervals) | After sorting, only neighbours can interact |
| "prefix", "autocomplete", "starts with" | [Trie](/dsa/tries) | Shared beginnings stored once, walked letter by letter |
| "range sum/min, many queries", "updates between queries" | [Prefix sums / Fenwick](/dsa/segment-and-fenwick-trees) | Precompute block answers; reuse forever |
| "linked list" + "cycle / middle / k-th from end" | [Fast & slow pointers](/dsa/linked-lists) | Different speeds reveal structure without extra memory |

Two suspects at once is normal ("sorted" + "pair" → two pointers on a sorted
array). The table narrows fifteen options to two — your worked examples
settle the rest.

## The 7-step routine

Same moves, every problem, out loud. Interviewers grade the moves as much as
the code.

1. **Restate the problem in your own words.** One sentence. If you can't,
   you don't understand it yet — and discovering that now costs nothing.
2. **Interrogate the edges.** Empty input? Duplicates? Negative numbers?
   Sorted already? How big is n? (n ≤ 15 whispers *backtracking is fine*;
   n = 10⁵ shouts *nothing slower than O(n log n)*.)
3. **Run the decoder.** Which phrases above appear? Name 1–2 candidate
   patterns *out loud* — "all orderings, so this smells like backtracking."
4. **Solve it by hand first.** Take a 5-element example and get the answer
   with pencil logic. Watch what your own brain does — your hand-method
   usually *is* the algorithm.
5. **State the brute force and its cost.** Twenty seconds: "check every
   pair, O(n²)." Now you have a baseline, and improving it has direction:
   what work is being repeated? Repeated lookups → hash. Repeated halves →
   binary search. Repeated sub-answers → DP.
6. **Code the chosen pattern's template.** Not from inspiration — from the
   template you drilled. Say the invariant while you type ("window is always
   valid after this while-loop").
7. **Test like a skeptic.** Trace the smallest real example, then one edge
   case from step 2. Fix quietly, don't panic loudly.

<Callout type="tip" title="The honest version of 'I don't know'">
Stuck after the decoder? Say: "Brute force is O(n²); I'm looking for the
repeated work to eliminate." That sentence — naming the baseline and the
search direction — earns more points than silent staring ever lost.
</Callout>

<QA q="Interviewer cheat-sheet: what do you do in the first two minutes after hearing a problem?">

Restate the problem in one sentence and confirm it. Ask about edges: input
size, duplicates, negatives, empty input, sorted or not. Then run the pattern
decoder on the wording — phrases like "all ways" (backtracking), "how many
ways/min cost" (DP), "top k" (heap), "longest substring with…" (sliding
window) name their pattern directly. Name your 1–2 suspects out loud, state
the brute force and its cost, and only then start designing. No code before
minute five.

</QA>

<QA q="How do you decide between backtracking and DP when a problem involves making choices?">

Ask what the output is. If it's the *list of solutions themselves* ("return
all valid combinations") you must enumerate — backtracking. If it's a *count
or a best value* ("how many ways", "minimum coins") and the same smaller
sub-questions recur, you don't need the paths — store one answer per
sub-question in a table: DP. Quick test: could two different choice-sequences
land in the same sub-problem? If yes, a table collapses them; enumeration
would redo them.

</QA>

## The same thinking in Java and C++

The decoder and 7-step routine are language-agnostic. Here are the two canonical patterns from the ThinkThrough exercises above in Python, Java, and C++:

```python
# Two Sum — O(n) hash map, Python
def two_sum(nums, target):
    seen = {}                       # value -> index
    for i, x in enumerate(nums):
        if target - x in seen:      # partner already seen?
            return [seen[target - x], i]
        seen[x] = i                 # remember me for future partners
    return []

# Valid Parentheses — O(n) stack, Python
def is_valid(s):
    pairs = {')': '(', ']': '[', '}': '{'}
    stack = []
    for ch in s:
        if ch in '([{':
            stack.append(ch)            # new open business
        else:
            if not stack or stack[-1] != pairs[ch]:
                return False            # fail 1 or 2
            stack.pop()                 # matched — cross it off
    return not stack                    # fail 3 if leftovers
```

```java
// Two Sum in Java
import java.util.HashMap;

public class TwoSum {
    public int[] twoSum(int[] nums, int target) {
        HashMap<Integer, Integer> seen = new HashMap<>();  // value → index
        for (int i = 0; i < nums.length; i++) {
            int partner = target - nums[i];
            if (seen.containsKey(partner)) {
                return new int[]{seen.get(partner), i};
            }
            seen.put(nums[i], i);  // remember for future partners
        }
        return new int[]{};
    }
}

// Valid Parentheses — O(n) stack, Java
import java.util.Stack;

public class ValidParentheses {
    public boolean isValid(String s) {
        Stack<Character> stack = new Stack<>();
        for (char ch : s.toCharArray()) {
            if (ch == '(' || ch == '[' || ch == '{') {
                stack.push(ch);
            } else {
                if (stack.isEmpty()) return false;    // nothing to close
                char top = stack.pop();
                if (ch == ')' && top != '(') return false;
                if (ch == ']' && top != '[') return false;
                if (ch == '}' && top != '{') return false;
            }
        }
        return stack.isEmpty();  // unmatched openers
    }
}
```

```cpp
// Two Sum — O(n) hash map, C++
#include <vector>
#include <unordered_map>
using namespace std;

vector<int> twoSum(vector<int>& nums, int target) {
    unordered_map<int, int> seen;  // value -> index
    for (int i = 0; i < (int)nums.size(); i++) {
        int partner = target - nums[i];
        if (seen.count(partner)) {
            return {seen[partner], i};
        }
        seen[nums[i]] = i;  // remember for future partners
    }
    return {};
}

// Valid Parentheses — O(n) stack, C++
#include <stack>
#include <string>

bool isValid(string s) {
    stack<char> stk;
    for (char ch : s) {
        if (ch == '(' || ch == '[' || ch == '{') {
            stk.push(ch);
        } else {
            if (stk.empty()) return false;
            char top = stk.top(); stk.pop();
            if (ch == ')' && top != '(') return false;
            if (ch == ']' && top != '[') return false;
            if (ch == '}' && top != '{') return false;
        }
    }
    return stk.empty();
}
```
