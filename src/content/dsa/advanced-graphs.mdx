## Past traversal

[BFS/DFS](/dsa/graphs-bfs-dfs) answer reachability and unweighted shortest paths. Weighted
graphs need heavier machinery — and interviews at **Google, Amazon, Uber** (maps/routing)
lean on it. The skill isn't memorizing five algorithms; it's the **decision table**:

| Need | Use | Cost | Constraint |
|---|---|---|---|
| Shortest path, **non-negative** weights | **Dijkstra** | O((V+E) log V) | no negative edges |
| Shortest path, **negative** edges / detect negative cycle | **Bellman-Ford** | O(V·E) | — |
| **All-pairs** shortest paths | **Floyd-Warshall** | O(V³) | small V |
| Shortest path on a **DAG** | topological sort + relax | O(V+E) | acyclic |
| **Min spanning tree** | **Kruskal** (+ [union-find](/dsa/union-find)) / **Prim** | O(E log E) | undirected, weighted |
| **Max flow / min cut**, bipartite matching | **Edmonds-Karp / Dinic** | poly | flow network |

## Dijkstra — the workhorse

**When:** single-source shortest path on a weighted graph with **non-negative**
edges — maps, routing, minimum-cost reachability.

**How it works:** it's BFS with a **min-heap** instead of a plain queue. Always pull
out the closest unsettled node, then *relax* its edges (lower a neighbour's distance
if the path through this node is cheaper). It's **correct only because** weights are
non-negative: once you pop a node, no later path can beat its distance — adding more
non-negative edges can't get cheaper — so it's final. The `if d > dist...: continue`
line skips stale heap entries from earlier, larger estimates.

```python
import heapq
def dijkstra(graph, src):           # graph: {u: [(v, w), ...]}
    dist = {src: 0}
    pq = [(0, src)]
    while pq:
        d, u = heapq.heappop(pq)
        if d > dist.get(u, float('inf')): continue   # stale entry
        for v, w in graph[u]:
            nd = d + w
            if nd < dist.get(v, float('inf')):
                dist[v] = nd
                heapq.heappush(pq, (nd, v))
    return dist
```

## Bellman-Ford — when edges go negative

**When:** edges can be **negative** (Dijkstra's greedy assumption fails), or you
must **detect a negative cycle**.

**How it works:** just relax **every** edge, `V−1` times. The key fact: after round
k, every shortest path using at most k edges is already correct — and a simple
shortest path has at most V−1 edges, so V−1 rounds settle them all. Then one *extra*
round that still improves means a **negative cycle** (you could loop it forever to
drive the cost down). Slower than Dijkstra at O(V·E), but that's the price of
handling negatives:

```python
def bellman_ford(edges, V, src):     # edges: [(u, v, w), ...]
    dist = [float('inf')] * V
    dist[src] = 0
    for _ in range(V - 1):
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
    for u, v, w in edges:            # a further improvement ⇒ negative cycle
        if dist[u] + w < dist[v]:
            raise ValueError("negative cycle")
    return dist
```

## MST & flow in one breath

- **MST** — connect every node with minimum total edge weight (n−1 edges, no cycle);
  think "cheapest cabling to wire up all the cities." **Kruskal:** sort edges, add the
  cheapest that doesn't form a cycle (cycle check via
  [union-find](/dsa/union-find)). **Prim:** grow one tree outward with a heap, always
  taking the cheapest edge to a *new* node — like Dijkstra, but comparing edge weight
  instead of total distance from a source.
- **Max-flow / min-cut:** push flow along augmenting paths until none remain; the
  max-flow equals the **min-cut** (max-flow min-cut theorem). Most interview "flow"
  problems are really **bipartite matching** — model as a flow network with a source → left
  → right → sink. Know the framing even if you rarely code Dinic from scratch.

<Callout type="warn" title="Pick the algorithm from the constraints">
Negative edges? Dijkstra is out — use Bellman-Ford. Need *all* pairs and V is small?
Floyd-Warshall's three nested loops. Extra constraint like 'K stops'? Bellman-Ford rounds
or a state-augmented Dijkstra. Saying *why* you rejected the others is the signal — the
decision table above is the actual interview content.
</Callout>

<QA q="When do you use Dijkstra vs Bellman-Ford vs Floyd-Warshall?">

**Dijkstra** for single-source shortest paths with **non-negative** weights — greedy with a
heap, O((V+E) log V); it's the default. **Bellman-Ford** when edges can be **negative** or
you must **detect a negative cycle**, or when an extra constraint like "at most K hops"
maps onto its round structure — O(V·E). **Floyd-Warshall** when you need **all-pairs**
shortest paths and V is small — three nested loops, O(V³). The constraint in the prompt
(negative edges? all pairs? hop limit?) picks the algorithm.

</QA>

<QA q="What is the relationship between max-flow and min-cut, and where does it show up?">

The **max-flow min-cut theorem**: the maximum flow from source to sink equals the capacity
of the minimum cut separating them. Practically, many interview problems that don't look
like flow — especially **bipartite matching** (assign workers to tasks, courses to slots) —
are modeled as a flow network (source → left set → right set → sink, unit capacities) and
solved with Edmonds-Karp/Dinic. You rarely code the full algorithm in an interview, but
recognizing "this is a matching/flow problem" and explaining the source-sink modeling is
the win.

</QA>
