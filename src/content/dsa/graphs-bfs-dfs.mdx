## What even is a graph?

A **graph** is a set of **nodes** (also called vertices, V) connected by **edges** (E). That's it. But this
deceptively simple definition captures almost every relationship that matters in computing:

- **Social networks** — users are nodes, friendships are edges
- **Maps / GPS** — cities are nodes, roads with distances are edges
- **The internet** — servers are nodes, cables/links are edges
- **Dependencies** — packages are nodes, "A requires B" is a directed edge
- **Scheduling** — tasks are nodes, "do A before B" is an ordering edge
- **Compilers** — variables are nodes, "A is used by B" is a data-flow edge

If you understand graphs deeply, you understand a huge slice of the real world. This page goes from zero to every
algorithm you'll ever need — in interviews, in production, and in competitive programming.

## Part 1 — Fundamentals & Representation

### Vocabulary (say these correctly in interviews)

| Term | Meaning |
|---|---|
| **Vertex / Node** | A point in the graph (often labeled 0…n-1) |
| **Edge** | A connection between two vertices |
| **Directed (digraph)** | Edges have direction: A→B ≠ B→A |
| **Undirected** | Edges go both ways: A-B means A↔B |
| **Weighted** | Each edge has a cost/distance |
| **Unweighted** | All edges are equal (or weight = 1) |
| **Degree** | Number of edges touching a node |
| **In-degree / Out-degree** | For directed: edges coming in / going out |
| **Path** | A sequence of nodes connected by edges |
| **Cycle** | A path that starts and ends at the same node |
| **DAG** | Directed Acyclic Graph — directed, no cycles |
| **Connected** | Every node is reachable from every other (undirected) |
| **Strongly Connected** | Every node reachable from every other in a *directed* graph |
| **Component** | A maximal connected subgraph |
| **Sparse** | Few edges: E ≈ V |
| **Dense** | Many edges: E ≈ V² |
| **Tree** | Connected, undirected, no cycles — exactly V-1 edges |
| **Forest** | Collection of trees (no cycles, possibly disconnected) |

### Three ways to represent a graph

**1. Adjacency List** (default — use this 95% of the time)

```python
# n nodes labeled 0..n-1
from collections import defaultdict

adj = defaultdict(list)
# For undirected: add both directions
adj[0].append(1)
adj[1].append(0)
adj[1].append(2)
adj[2].append(1)

# For weighted graphs: store (neighbor, weight)
adj[0].append((1, 5))   # edge 0→1 with weight 5
```

```java
// Java
List<List<Integer>> adj = new ArrayList<>();
for (int i = 0; i < n; i++) adj.add(new ArrayList<>());
adj.get(0).add(1);
adj.get(1).add(0);  // undirected

// Weighted
List<List<int[]>> wAdj = new ArrayList<>();
wAdj.get(0).add(new int[]{1, 5}); // neighbor=1, weight=5
```

**Space:** O(V + E) — stores only actual edges. **Traversal:** O(V + E).

**2. Adjacency Matrix**

```python
# n × n grid; matrix[i][j] = weight of edge i→j (0 or ∞ if no edge)
n = 5
matrix = [[0] * n for _ in range(n)]
matrix[0][1] = 1  # edge 0→1
matrix[1][0] = 1  # undirected: also add reverse
```

**Space:** O(V²) — 1000 nodes = 1 million cells. **Edge lookup:** O(1). Use only for dense graphs or when
you need instant edge-weight lookup (Floyd-Warshall).

**3. Edge List**

```python
edges = [(0, 1, 5), (1, 2, 3), (2, 3, 7)]  # (u, v, weight)
```

Useful for sorting edges by weight (Kruskal's MST). O(E) space.

### Building a graph from input

```python
# Standard competitive programming input: n nodes, m edges
n, m = map(int, input().split())
adj = [[] for _ in range(n)]
for _ in range(m):
    u, v = map(int, input().split())
    adj[u].append(v)
    adj[v].append(u)  # remove if directed

# Weighted
adj = [[] for _ in range(n)]
for _ in range(m):
    u, v, w = map(int, input().split())
    adj[u].append((v, w))
    adj[v].append((u, w))  # remove if directed
```

<Callout type="tip" title="When to use which representation">
- **Adjacency list**: sparse graphs, most interview problems, BFS/DFS — your default.
- **Adjacency matrix**: dense graphs, Floyd-Warshall, when you need O(1) edge existence checks.
- **Edge list**: Kruskal's MST (need to sort edges), input parsing convenience.
</Callout>

## Part 2 — BFS (Breadth-First Search)

### The core idea

BFS explores nodes **level by level** — first all nodes at distance 1, then all at distance 2, etc. It uses a
**queue** (FIFO). This level-by-level property is the key: the first time you reach a node in BFS, you've
found the **shortest path** (fewest edges) to it.

```
Graph:  0 - 1 - 3
        |   |
        2 - 4

BFS from 0: visit 0, then {1,2}, then {3,4}
Distances: 0→0=0, 0→1=1, 0→2=1, 0→3=2, 0→4=2
```

### Complete BFS implementation

```python
from collections import deque

def bfs(adj, start, n):
    """
    BFS traversal — returns distance from start to every node.
    -1 means unreachable (disconnected graph).
    """
    dist = [-1] * n
    dist[start] = 0
    q = deque([start])

    while q:
        node = q.popleft()
        for neighbor in adj[node]:
            if dist[neighbor] == -1:        # not visited
                dist[neighbor] = dist[node] + 1
                q.append(neighbor)          # ✅ mark visited ON ENQUEUE

    return dist
```

```java
// Java BFS
int[] bfs(List<List<Integer>> adj, int start, int n) {
    int[] dist = new int[n];
    Arrays.fill(dist, -1);
    dist[start] = 0;
    Queue<Integer> q = new LinkedList<>();
    q.offer(start);
    while (!q.isEmpty()) {
        int node = q.poll();
        for (int nb : adj.get(node)) {
            if (dist[nb] == -1) {
                dist[nb] = dist[node] + 1;
                q.offer(nb);
            }
        }
    }
    return dist;
}
```

<Callout type="warn" title="The #1 BFS Bug — Mark on Enqueue, NOT Dequeue">
Always mark a node as visited **when you add it to the queue**, not when you remove it. If you mark on
dequeue, the same node gets added to the queue multiple times before it's processed — causing wrong distances
and potentially infinite loops. This single bug fails more BFS solutions than any other mistake.
</Callout>

### BFS to find the actual path (not just distance)

```python
def bfs_path(adj, start, end, n):
    """Returns the shortest path from start to end, or [] if unreachable."""
    prev = [-1] * n
    visited = [False] * n
    visited[start] = True
    q = deque([start])

    while q:
        node = q.popleft()
        if node == end:
            break
        for nb in adj[node]:
            if not visited[nb]:
                visited[nb] = True
                prev[nb] = node     # remember how we got here
                q.append(nb)

    # Reconstruct path by walking backwards
    if not visited[end]:
        return []   # unreachable
    path = []
    cur = end
    while cur != -1:
        path.append(cur)
        cur = prev[cur]
    return path[::-1]   # reverse to get start→end
```

### Multi-source BFS

When you need distances from **multiple starting points simultaneously** (e.g., "distance from nearest
warehouse," "nearest exit in a maze"), initialize the queue with all sources at distance 0:

```python
def multi_source_bfs(adj, sources, n):
    """
    BFS from multiple sources simultaneously.
    Example: 01 Matrix — distance from each cell to nearest 0.
    """
    dist = [-1] * n
    q = deque()
    for s in sources:
        dist[s] = 0
        q.append(s)

    while q:
        node = q.popleft()
        for nb in adj[node]:
            if dist[nb] == -1:
                dist[nb] = dist[node] + 1
                q.append(nb)
    return dist
```

### Level-by-level BFS

When you need to process nodes level by level (e.g., "minimum steps", "binary tree level order"):

```python
def bfs_levels(adj, start):
    """Returns list of levels: levels[0] = [start], levels[1] = [all at dist 1], ..."""
    visited = {start}
    q = deque([start])
    levels = []

    while q:
        level = []
        for _ in range(len(q)):     # process exactly this level's nodes
            node = q.popleft()
            level.append(node)
            for nb in adj[node]:
                if nb not in visited:
                    visited.add(nb)
                    q.append(nb)
        levels.append(level)
    return levels
```

### BFS on a 2D grid

Grid problems are just graphs where nodes are cells and edges connect adjacent cells:

```python
def bfs_grid(grid, start_r, start_c):
    """BFS on a 2D grid. Returns distance from start to every reachable cell."""
    rows, cols = len(grid), len(grid[0])
    dist = [[-1] * cols for _ in range(rows)]
    dist[start_r][start_c] = 0
    q = deque([(start_r, start_c)])
    directions = [(0,1),(0,-1),(1,0),(-1,0)]  # right, left, down, up

    while q:
        r, c = q.popleft()
        for dr, dc in directions:
            nr, nc = r + dr, c + dc
            if 0 <= nr < rows and 0 <= nc < cols and dist[nr][nc] == -1 and grid[nr][nc] != '#':
                dist[nr][nc] = dist[r][c] + 1
                q.append((nr, nc))
    return dist
```

## Part 3 — DFS (Depth-First Search)

### The core idea

DFS dives as deep as possible along one path before backtracking. It naturally uses the **call stack**
(recursive) or an explicit **stack**. DFS is the tool for: connectivity, all paths, cycle detection,
topological order, strongly connected components, bridges, and articulation points.

### Recursive DFS (clean and standard)

```python
def dfs(adj, node, visited):
    """Visit all nodes reachable from `node`."""
    visited[node] = True
    for nb in adj[node]:
        if not visited[nb]:
            dfs(adj, nb, visited)

# Count connected components
def count_components(adj, n):
    visited = [False] * n
    components = 0
    for i in range(n):
        if not visited[i]:
            dfs(adj, i, visited)
            components += 1
    return components
```

### Iterative DFS (when recursion limit is a concern)

```python
def dfs_iterative(adj, start, n):
    visited = [False] * n
    stack = [start]
    order = []

    while stack:
        node = stack.pop()
        if visited[node]:
            continue
        visited[node] = True
        order.append(node)
        for nb in adj[node]:      # note: reversed order vs recursive DFS
            if not visited[nb]:
                stack.append(nb)
    return order
```

<Callout type="tip" title="Recursive vs Iterative DFS">
Recursive DFS is cleaner and is the standard in interviews. Use iterative DFS only when the graph could be
very deep (n ≈ 10⁵) to avoid Python's recursion limit (sys.setrecursionlimit or iterative). In Java/C++,
the default stack is much deeper, so recursion is almost always fine.
</Callout>

### DFS with entry/exit timestamps (crucial for advanced algorithms)

```python
timer = [0]
entry = [0] * n   # when we first visit node
exit_  = [0] * n  # when we finish processing node and backtrack

def dfs_time(adj, node, visited):
    visited[node] = True
    entry[node] = timer[0]; timer[0] += 1
    for nb in adj[node]:
        if not visited[nb]:
            dfs_time(adj, nb, visited)
    exit_[node] = timer[0]; timer[0] += 1
```

Why does this matter? Entry/exit times let you check **subtree relationships** in O(1):
- `u` is an ancestor of `v` iff `entry[u] < entry[v]` and `exit[v] < exit[u]`

## Part 4 — Cycle Detection

### Cycle in an undirected graph

Use DFS. An undirected graph has a cycle if you reach an already-visited node that **isn't** your direct parent:

```python
def has_cycle_undirected(adj, n):
    visited = [False] * n

    def dfs(node, parent):
        visited[node] = True
        for nb in adj[node]:
            if not visited[nb]:
                if dfs(nb, node):
                    return True
            elif nb != parent:          # visited AND not parent = cycle!
                return True
        return False

    for i in range(n):
        if not visited[i]:
            if dfs(i, -1):
                return True
    return False
```

<Callout type="warn" title="The Parent Check Trap">
For undirected graphs: when you see a visited neighbor, check if it's the parent. If yes, it's just the
edge you came from — not a cycle. If no, you've found a cycle. This check is easy to forget.

**Edge case:** if there are multiple edges between the same two nodes (multigraph), pass parent *edge id*
instead of parent *node* to avoid false negatives.
</Callout>

### Cycle in a directed graph

For directed graphs, track nodes currently on the **recursion stack** (gray nodes). An edge to a gray node
is a back edge = cycle:

```python
def has_cycle_directed(adj, n):
    # 0 = unvisited, 1 = in current path (gray), 2 = fully processed (black)
    color = [0] * n

    def dfs(node):
        color[node] = 1      # mark as "in progress"
        for nb in adj[node]:
            if color[nb] == 1:   # back edge to an in-progress node = cycle
                return True
            if color[nb] == 0:   # unvisited
                if dfs(nb):
                    return True
        color[node] = 2      # fully processed — no cycle from here
        return False

    for i in range(n):
        if color[i] == 0:
            if dfs(i):
                return True
    return False
```

| Scenario | Method |
|---|---|
| Undirected cycle | DFS + parent check |
| Directed cycle | DFS + 3-color (white/gray/black) |
| Either (static graph) | Union-Find (for undirected; see [Union-Find](/dsa/union-find)) |
| DAG verification | Topological sort — if order has fewer than V nodes, cycle exists |

## Part 5 — Topological Sort (DAGs)

A **topological order** is a linear ordering of nodes in a DAG such that for every directed edge u→v,
u comes before v. Think: build order, task scheduling, course prerequisites.

### Method 1: Kahn's Algorithm (BFS-based)

Repeatedly remove nodes with in-degree 0 (no prerequisites). If you can't remove all nodes, a cycle exists.

```python
from collections import deque

def topological_sort_kahn(adj, n):
    """
    Returns topological order of nodes, or [] if a cycle exists.
    adj: adjacency list (directed edges)
    """
    indegree = [0] * n
    for u in range(n):
        for v in adj[u]:
            indegree[v] += 1

    # Start with all nodes that have no prerequisites
    q = deque([i for i in range(n) if indegree[i] == 0])
    order = []

    while q:
        node = q.popleft()
        order.append(node)
        for nb in adj[node]:
            indegree[nb] -= 1
            if indegree[nb] == 0:
                q.append(nb)

    return order if len(order) == n else []   # [] means cycle detected
```

### Method 2: DFS Post-order

After fully processing a node (visiting all its descendants), add it to the front. The resulting list is
topologically ordered:

```python
def topological_sort_dfs(adj, n):
    visited = [False] * n
    order = []

    def dfs(node):
        visited[node] = True
        for nb in adj[node]:
            if not visited[nb]:
                dfs(nb)
        order.append(node)      # add AFTER exploring all neighbors

    for i in range(n):
        if not visited[i]:
            dfs(i)

    return order[::-1]          # reverse: last-finished comes first
```

### Classic topological sort problems

```python
# Course Schedule (LeetCode 207): can you finish all courses?
# = can you topologically sort the course dependency DAG?
def can_finish(numCourses, prerequisites):
    adj = [[] for _ in range(numCourses)]
    indegree = [0] * numCourses
    for a, b in prerequisites:
        adj[b].append(a)      # b must be taken before a
        indegree[a] += 1
    q = deque([i for i in range(numCourses) if indegree[i] == 0])
    taken = 0
    while q:
        node = q.popleft()
        taken += 1
        for nb in adj[node]:
            indegree[nb] -= 1
            if indegree[nb] == 0:
                q.append(nb)
    return taken == numCourses
```

<Callout type="tip" title="Kahn's vs DFS Topological Sort">
Both are O(V+E). Use **Kahn's** when: you need cycle detection as a side effect, you want a "by-level"
execution plan, or BFS feels more natural. Use **DFS post-order** when: you're already doing DFS for other
reasons, or computing finishing times (needed for Kosaraju's SCC algorithm).
</Callout>

## Part 6 — Shortest Paths

### Overview: which algorithm to use?

| Scenario | Algorithm | Complexity |
|---|---|---|
| Unweighted graph | BFS | O(V + E) |
| Weighted, non-negative edges, single source | **Dijkstra** | O((V + E) log V) |
| Weighted, negative edges, single source | **Bellman-Ford** | O(VE) |
| Negative cycle detection | Bellman-Ford | O(VE) |
| All pairs shortest path | **Floyd-Warshall** | O(V³) |
| All pairs, sparse graph | Dijkstra × V times | O(VE log V) |
| DAG shortest path | Topological sort + relax | O(V + E) |
| Unit weights with obstacles | BFS / 0-1 BFS | O(V + E) |

### Dijkstra's Algorithm

The go-to for **weighted graphs with non-negative edge weights**. Uses a min-heap (priority queue).
Works exactly like BFS but replaces the queue with a heap ordered by distance.

```python
import heapq

def dijkstra(adj, src, n):
    """
    Shortest distance from src to all nodes.
    adj[u] = list of (neighbor, weight)
    Returns dist array; -1 means unreachable.
    """
    dist = [float('inf')] * n
    dist[src] = 0
    heap = [(0, src)]   # (distance, node)

    while heap:
        d, node = heapq.heappop(heap)

        if d > dist[node]:      # stale entry — skip
            continue

        for nb, w in adj[node]:
            new_dist = dist[node] + w
            if new_dist < dist[nb]:
                dist[nb] = new_dist
                heapq.heappush(heap, (new_dist, nb))

    return [d if d != float('inf') else -1 for d in dist]
```

```java
// Java Dijkstra
int[] dijkstra(List<List<int[]>> adj, int src, int n) {
    int[] dist = new int[n];
    Arrays.fill(dist, Integer.MAX_VALUE);
    dist[src] = 0;
    PriorityQueue<int[]> pq = new PriorityQueue<>(Comparator.comparingInt(a -> a[0]));
    pq.offer(new int[]{0, src});

    while (!pq.isEmpty()) {
        int[] curr = pq.poll();
        int d = curr[0], node = curr[1];
        if (d > dist[node]) continue;  // stale
        for (int[] edge : adj.get(node)) {
            int nb = edge[0], w = edge[1];
            if (dist[node] + w < dist[nb]) {
                dist[nb] = dist[node] + w;
                pq.offer(new int[]{dist[nb], nb});
            }
        }
    }
    return dist;
}
```

**Why it fails with negative edges:** Dijkstra assumes that once a node is popped from the heap (shortest
distance known), it won't be updated again. Negative edges can create shorter paths after a node is "settled,"
breaking this assumption.

### Dijkstra with path reconstruction

```python
def dijkstra_path(adj, src, dst, n):
    dist = [float('inf')] * n
    prev = [-1] * n
    dist[src] = 0
    heap = [(0, src)]

    while heap:
        d, node = heapq.heappop(heap)
        if d > dist[node]:
            continue
        if node == dst:
            break
        for nb, w in adj[node]:
            if dist[node] + w < dist[nb]:
                dist[nb] = dist[node] + w
                prev[nb] = node
                heapq.heappush(heap, (dist[nb], nb))

    # Reconstruct path
    if dist[dst] == float('inf'):
        return [], -1
    path, cur = [], dst
    while cur != -1:
        path.append(cur)
        cur = prev[cur]
    return path[::-1], dist[dst]
```

### 0-1 BFS (when edges have weight 0 or 1 only)

When edge weights are only 0 or 1, use a **deque** instead of a heap for O(V+E):

```python
from collections import deque

def bfs_01(adj, src, n):
    """
    0-1 BFS: adj[u] = list of (neighbor, weight) where weight ∈ {0, 1}
    Weight-0 edges go to the front of the deque (process first).
    Weight-1 edges go to the back (process later, like BFS level).
    """
    dist = [float('inf')] * n
    dist[src] = 0
    dq = deque([src])

    while dq:
        node = dq.popleft()
        for nb, w in adj[node]:
            if dist[node] + w < dist[nb]:
                dist[nb] = dist[node] + w
                if w == 0:
                    dq.appendleft(nb)    # free edge — process next
                else:
                    dq.append(nb)        # cost edge — process later
    return dist
```

### Bellman-Ford Algorithm

Handles **negative edge weights** and detects **negative cycles**. Relax every edge V-1 times.

```python
def bellman_ford(n, edges, src):
    """
    n: number of nodes (0..n-1)
    edges: list of (u, v, weight)
    Returns dist array; if negative cycle reachable from src, some dist = -inf.
    """
    dist = [float('inf')] * n
    dist[src] = 0

    # Relax all edges V-1 times
    for _ in range(n - 1):
        updated = False
        for u, v, w in edges:
            if dist[u] != float('inf') and dist[u] + w < dist[v]:
                dist[v] = dist[u] + w
                updated = True
        if not updated:
            break   # early termination: converged

    # Detect negative cycles: if we can still relax, there's a negative cycle
    for u, v, w in edges:
        if dist[u] != float('inf') and dist[u] + w < dist[v]:
            dist[v] = float('-inf')    # mark as negative-cycle-affected

    return dist
```

**Why V-1 iterations?** A shortest path without a negative cycle visits at most V-1 edges (otherwise it
would revisit a node, forming a cycle). Each iteration guarantees we've found optimal paths using at most
`i` edges after the `i`-th iteration.

### Floyd-Warshall (All-Pairs Shortest Path)

Find shortest distances between **all pairs** of nodes. O(V³) time, O(V²) space.

```python
def floyd_warshall(n, edges):
    """
    Returns dist[i][j] = shortest distance from i to j.
    Use when: V ≤ ~500, need all-pairs distances, or need to handle negative edges.
    """
    INF = float('inf')
    dist = [[INF] * n for _ in range(n)]
    for i in range(n):
        dist[i][i] = 0   # distance to self = 0
    for u, v, w in edges:
        dist[u][v] = min(dist[u][v], w)
        dist[v][u] = min(dist[v][u], w)   # remove for directed

    for k in range(n):          # intermediate node
        for i in range(n):      # source
            for j in range(n):  # destination
                if dist[i][k] + dist[k][j] < dist[i][j]:
                    dist[i][j] = dist[i][k] + dist[k][j]

    # Check negative cycles: if dist[i][i] < 0, i is on a negative cycle
    for i in range(n):
        if dist[i][i] < 0:
            print(f"Negative cycle detected involving node {i}")

    return dist
```

**The insight:** `dist[i][j]` after using intermediate nodes `{0..k}` = min(using k as intermediate,
not using k). This recurrence lets you build up all-pairs distances bottom-up.

### Shortest path in a DAG (faster than Dijkstra)

If the graph is a DAG (no cycles), topological sort + one relaxation pass is O(V+E):

```python
def dag_shortest_path(adj, src, n):
    """Shortest path in a DAG — works with negative edges too."""
    order = topological_sort_kahn(adj, n)   # topological order
    dist = [float('inf')] * n
    dist[src] = 0

    for node in order:
        if dist[node] == float('inf'):
            continue
        for nb, w in adj[node]:
            if dist[node] + w < dist[nb]:
                dist[nb] = dist[node] + w
    return dist
```

## Part 7 — Minimum Spanning Trees (MST)

A **Minimum Spanning Tree** of a connected, weighted, undirected graph is a spanning tree (connects all V nodes
with V-1 edges, no cycles) with the minimum total edge weight. Applications: cheapest network connecting all
cities, laying cables, clustering.

### Kruskal's Algorithm (Edge-based, uses Union-Find)

Sort all edges by weight, greedily add each edge if it doesn't form a cycle:

```python
def kruskal(n, edges):
    """
    n: number of nodes (0..n-1)
    edges: list of (weight, u, v)
    Returns (MST weight, MST edges)
    """
    edges.sort()   # sort by weight ascending
    parent = list(range(n))
    rank = [0] * n

    def find(x):
        if parent[x] != x:
            parent[x] = find(parent[x])
        return parent[x]

    def union(x, y):
        rx, ry = find(x), find(y)
        if rx == ry:
            return False
        if rank[rx] < rank[ry]:
            rx, ry = ry, rx
        parent[ry] = rx
        if rank[rx] == rank[ry]:
            rank[rx] += 1
        return True

    mst_weight = 0
    mst_edges = []
    for w, u, v in edges:
        if union(u, v):          # doesn't form a cycle
            mst_weight += w
            mst_edges.append((u, v, w))
            if len(mst_edges) == n - 1:   # MST is complete
                break

    return mst_weight, mst_edges
```

**Complexity:** O(E log E) for sorting + O(E α(V)) for Union-Find ≈ **O(E log E)**.

### Prim's Algorithm (Node-based, uses a heap)

Grow the MST one node at a time. Start from any node, always add the cheapest edge connecting the current
MST to a new node:

```python
def prim(adj, n):
    """
    adj[u] = list of (neighbor, weight)
    Returns MST total weight.
    """
    visited = [False] * n
    heap = [(0, 0)]   # (cost to add this node to MST, node)
    mst_weight = 0

    while heap:
        cost, node = heapq.heappop(heap)
        if visited[node]:
            continue
        visited[node] = True
        mst_weight += cost

        for nb, w in adj[node]:
            if not visited[nb]:
                heapq.heappush(heap, (w, nb))

    return mst_weight
```

**Complexity:** O((V + E) log V) with a binary heap.

| | Kruskal | Prim |
|---|---|---|
| Better for | Sparse graphs (E ≈ V) | Dense graphs (E ≈ V²) |
| Data structure | Union-Find + sorted edges | Min-heap |
| Implementation | Slightly longer | Slightly shorter (Dijkstra-like) |
| Key idea | Global edge sort | Local greedy expansion |

## Part 8 — Strongly Connected Components (SCC)

A **Strongly Connected Component** is a maximal set of nodes where every node is reachable from every
other node (in a **directed** graph). Real uses: find "groups" in social networks, detect feedback loops
in dependency graphs, condense a DAG.

### Kosaraju's Algorithm (Two-pass DFS)

```python
def kosaraju(adj, n):
    """
    Returns list of SCCs, each SCC is a list of nodes.
    adj: adjacency list of directed graph
    """
    # Step 1: DFS on original graph, push nodes to stack in finish order
    visited = [False] * n
    stack = []

    def dfs1(node):
        visited[node] = True
        for nb in adj[node]:
            if not visited[nb]:
                dfs1(nb)
        stack.append(node)      # push after fully exploring

    for i in range(n):
        if not visited[i]:
            dfs1(i)

    # Step 2: Build reverse (transposed) graph
    radj = [[] for _ in range(n)]
    for u in range(n):
        for v in adj[u]:
            radj[v].append(u)

    # Step 3: DFS on reversed graph in reverse finish order
    visited = [False] * n
    sccs = []

    def dfs2(node, component):
        visited[node] = True
        component.append(node)
        for nb in radj[node]:
            if not visited[nb]:
                dfs2(nb, component)

    while stack:
        node = stack.pop()
        if not visited[node]:
            component = []
            dfs2(node, component)
            sccs.append(component)

    return sccs
```

**Why it works:** In the first pass, nodes finish in reverse topological order of SCCs. In the second pass
(on reversed graph), starting from the last-finished node of the first pass, we can only reach nodes within
the same SCC (because all cross-SCC edges in the original graph become cross-SCC edges in the opposite
direction in the reversed graph).

### Tarjan's Algorithm (Single-pass SCC, more efficient)

Tarjan's finds SCCs in a single DFS using a stack and discovery/low-link values:

```python
def tarjan(adj, n):
    """
    Single-pass SCC using Tarjan's algorithm.
    disc[u]: discovery time of u
    low[u]: lowest discovery time reachable from u's subtree
    """
    disc = [-1] * n
    low = [0] * n
    on_stack = [False] * n
    stack = []
    timer = [0]
    sccs = []

    def dfs(u):
        disc[u] = low[u] = timer[0]
        timer[0] += 1
        stack.append(u)
        on_stack[u] = True

        for v in adj[u]:
            if disc[v] == -1:           # tree edge
                dfs(v)
                low[u] = min(low[u], low[v])
            elif on_stack[v]:           # back edge to ancestor in current SCC
                low[u] = min(low[u], disc[v])

        # u is a root of an SCC if low[u] == disc[u]
        if low[u] == disc[u]:
            scc = []
            while True:
                w = stack.pop()
                on_stack[w] = False
                scc.append(w)
                if w == u:
                    break
            sccs.append(scc)

    for i in range(n):
        if disc[i] == -1:
            dfs(i)

    return sccs
```

## Part 9 — Bridges & Articulation Points

These are critical in network reliability analysis: which edges/nodes, if removed, disconnect the graph?

### Bridges (Critical Edges)

A **bridge** is an edge whose removal disconnects the graph:

```python
def find_bridges(adj, n):
    """
    Returns list of bridge edges (u, v).
    Uses DFS + low-link values.
    """
    disc = [-1] * n
    low = [0] * n
    timer = [0]
    bridges = []

    def dfs(u, parent):
        disc[u] = low[u] = timer[0]
        timer[0] += 1

        for v in adj[u]:
            if disc[v] == -1:           # unvisited neighbor
                dfs(v, u)
                low[u] = min(low[u], low[v])
                if low[v] > disc[u]:    # no back edge from v's subtree to u's ancestors
                    bridges.append((u, v))
            elif v != parent:           # back edge (not to parent)
                low[u] = min(low[u], disc[v])

    for i in range(n):
        if disc[i] == -1:
            dfs(i, -1)

    return bridges
```

### Articulation Points (Cut Vertices)

An **articulation point** is a node whose removal disconnects the graph:

```python
def find_articulation_points(adj, n):
    """
    Returns set of articulation points.
    """
    disc = [-1] * n
    low = [0] * n
    parent = [-1] * n
    timer = [0]
    ap = set()

    def dfs(u):
        disc[u] = low[u] = timer[0]
        timer[0] += 1
        children = 0    # number of children in DFS tree

        for v in adj[u]:
            if disc[v] == -1:
                children += 1
                parent[v] = u
                dfs(v)
                low[u] = min(low[u], low[v])

                # u is AP if: root with 2+ children, OR non-root with no back edge from subtree
                if parent[u] == -1 and children > 1:
                    ap.add(u)
                if parent[u] != -1 and low[v] >= disc[u]:
                    ap.add(u)
            elif v != parent[u]:
                low[u] = min(low[u], disc[v])

    for i in range(n):
        if disc[i] == -1:
            dfs(i)

    return ap
```

<Callout type="tip" title="Low-Link Values — The Core Concept">
`low[u]` = the minimum discovery time reachable from u's DFS subtree via **at most one** back edge.
An edge u→v is a **bridge** if `low[v] > disc[u]` (v can't reach back to u or u's ancestors).
A node u is an **articulation point** if any child v has `low[v] >= disc[u]` (no back edge "saves" the subtree).
</Callout>

## Part 10 — Advanced Graph Patterns

### Bipartite Graph Check

A graph is bipartite if its nodes can be 2-colored such that no two adjacent nodes share the same color.
Equivalently: no odd-length cycles.

```python
def is_bipartite(adj, n):
    """
    Returns (True, coloring) if bipartite, else (False, None).
    Uses BFS 2-coloring.
    """
    color = [-1] * n

    for start in range(n):
        if color[start] != -1:
            continue
        color[start] = 0
        q = deque([start])
        while q:
            node = q.popleft()
            for nb in adj[node]:
                if color[nb] == -1:
                    color[nb] = 1 - color[node]   # opposite color
                    q.append(nb)
                elif color[nb] == color[node]:    # same color = conflict
                    return False, None
    return True, color
```

### Graph Coloring (Greedy approach)

```python
def greedy_coloring(adj, n):
    """
    Assigns minimum colors such that no two adjacent nodes share a color.
    Not optimal for all graphs but works well in practice.
    """
    color = [-1] * n
    color[0] = 0

    for u in range(1, n):
        neighbor_colors = {color[v] for v in adj[u] if color[v] != -1}
        c = 0
        while c in neighbor_colors:
            c += 1
        color[u] = c

    return color, max(color) + 1   # (coloring, number of colors used)
```

### Flood Fill (Connected Components in a Grid)

```python
def flood_fill(grid, sr, sc, new_color):
    """
    Fills the connected region of the same color starting from (sr, sc).
    Used in paint programs, island counting, etc.
    """
    rows, cols = len(grid), len(grid[0])
    old_color = grid[sr][sc]
    if old_color == new_color:
        return grid

    def dfs(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols:
            return
        if grid[r][c] != old_color:
            return
        grid[r][c] = new_color
        dfs(r+1, c); dfs(r-1, c)
        dfs(r, c+1); dfs(r, c-1)

    dfs(sr, sc)
    return grid

def count_islands(grid):
    """Count number of connected land regions (classic LeetCode 200)."""
    rows, cols = len(grid), len(grid[0])
    count = 0

    def dfs(r, c):
        if r < 0 or r >= rows or c < 0 or c >= cols or grid[r][c] != '1':
            return
        grid[r][c] = '0'   # mark visited by sinking the island
        dfs(r+1,c); dfs(r-1,c); dfs(r,c+1); dfs(r,c-1)

    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == '1':
                dfs(r, c)
                count += 1
    return count
```

### Eulerian Path & Circuit

An **Eulerian Path** visits every **edge** exactly once. An **Eulerian Circuit** does the same and returns
to the start.

```
Eulerian Circuit exists iff:
  - Graph is connected (ignoring isolated nodes)
  - Every node has even degree

Eulerian Path (non-circuit) exists iff:
  - Exactly 2 nodes have odd degree (start and end of path)
```

```python
def find_euler_circuit(adj, n, m):
    """
    Hierholzer's algorithm: find Eulerian circuit.
    Works when all nodes have even degree.
    adj: adjacency list as {node: Counter of neighbors}
    """
    from collections import defaultdict
    degree = [0] * n
    for u in range(n):
        for v in adj[u]:
            degree[u] += 1

    # Find start node (any node with edges)
    start = next(i for i in range(n) if degree[i] > 0)
    stack = [start]
    circuit = []
    edge_count = defaultdict(lambda: defaultdict(int))

    # Build edge counts
    for u in range(n):
        for v in adj[u]:
            edge_count[u][v] += 1

    while stack:
        v = stack[-1]
        if any(edge_count[v][u] > 0 for u in edge_count[v]):
            # Find unused edge
            u = next(u for u in edge_count[v] if edge_count[v][u] > 0)
            stack.append(u)
            edge_count[v][u] -= 1
            edge_count[u][v] -= 1   # remove for directed graphs
        else:
            circuit.append(stack.pop())
    return circuit[::-1]
```

### Hamiltonian Path (Backtracking)

A **Hamiltonian Path** visits every **node** exactly once. No polynomial algorithm known — use backtracking
for small graphs (n ≤ ~20):

```python
def hamiltonian_path(adj, n):
    """Find Hamiltonian path using backtracking. O(n!) worst case."""
    visited = [False] * n
    path = []

    def backtrack(node):
        path.append(node)
        visited[node] = True
        if len(path) == n:
            return True
        for nb in adj[node]:
            if not visited[nb]:
                if backtrack(nb):
                    return True
        path.pop()
        visited[node] = False
        return False

    for start in range(n):
        if backtrack(start):
            return path
    return []
```

### Bellman-Ford for Negative Cycle Detection (Trading / Arbitrage)

```python
def detect_arbitrage(currencies, rates):
    """
    Detect currency arbitrage (negative cycle in log-rate graph).
    rates[i][j] = exchange rate from currency i to j.
    Arbitrage exists if you can profit by trading A→B→C→A.
    """
    import math
    n = len(currencies)
    # Transform: maximize product → minimize sum of negated logs
    dist = [float('inf')] * n
    dist[0] = 0

    # Build edge list with -log(rate) weights
    edges = []
    for i in range(n):
        for j in range(n):
            if i != j and rates[i][j] > 0:
                edges.append((i, j, -math.log(rates[i][j])))

    # Relax V-1 times
    for _ in range(n - 1):
        for u, v, w in edges:
            if dist[u] + w < dist[v]:
                dist[v] = dist[u] + w

    # Check for negative cycle (arbitrage opportunity)
    for u, v, w in edges:
        if dist[u] + w < dist[v]:
            return True   # arbitrage found!
    return False
```

```python
# ─── Word Ladder ──────────────────────────────────────────────────────────────
# Transform "hit" → "cog" changing one letter at a time, all intermediate words
# must be in wordList. Find minimum number of transformations.

def word_ladder(beginWord, endWord, wordList):
    word_set = set(wordList)
    if endWord not in word_set:
        return 0

    q = deque([(beginWord, 1)])
    visited = {beginWord}

    while q:
        word, steps = q.popleft()
        for i in range(len(word)):
            for c in 'abcdefghijklmnopqrstuvwxyz':
                next_word = word[:i] + c + word[i+1:]
                if next_word == endWord:
                    return steps + 1
                if next_word in word_set and next_word not in visited:
                    visited.add(next_word)
                    q.append((next_word, steps + 1))
    return 0

# ─── Rotting Oranges ───────────────────────────────────────────────────────────
# Multi-source BFS: rotten oranges spread to fresh neighbors each minute.
def oranges_rotting(grid):
    rows, cols = len(grid), len(grid[0])
    q = deque()
    fresh = 0

    for r in range(rows):
        for c in range(cols):
            if grid[r][c] == 2:
                q.append((r, c, 0))   # rotten: start source
            elif grid[r][c] == 1:
                fresh += 1

    time = 0
    dirs = [(0,1),(0,-1),(1,0),(-1,0)]
    while q:
        r, c, t = q.popleft()
        for dr, dc in dirs:
            nr, nc = r+dr, c+dc
            if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1:
                grid[nr][nc] = 2
                fresh -= 1
                time = t + 1
                q.append((nr, nc, t+1))

    return time if fresh == 0 else -1
```

### DFS Problems (paths, components, backtracking)

```python
# ─── All Paths from Source to Target in a DAG ──────────────────────────────────
def all_paths_source_target(graph):
    """Find all paths from node 0 to node n-1 in a DAG."""
    n = len(graph)
    result = []

    def dfs(node, path):
        if node == n - 1:
            result.append(list(path))
            return
        for nb in graph[node]:
            path.append(nb)
            dfs(nb, path)
            path.pop()

    dfs(0, [0])
    return result

# ─── Pacific Atlantic Water Flow ───────────────────────────────────────────────
# Which cells can flow water to both oceans? Multi-source DFS from both borders.
def pacific_atlantic(heights):
    rows, cols = len(heights), len(heights[0])
    pacific = set()    # cells reachable from pacific (top/left)
    atlantic = set()   # cells reachable from atlantic (bottom/right)

    def dfs(r, c, visited, prev_height):
        if (r, c) in visited or r < 0 or r >= rows or c < 0 or c >= cols:
            return
        if heights[r][c] < prev_height:    # water can't flow uphill
            return
        visited.add((r, c))
        for dr, dc in [(0,1),(0,-1),(1,0),(-1,0)]:
            dfs(r+dr, c+dc, visited, heights[r][c])

    for r in range(rows):
        dfs(r, 0, pacific, heights[r][0])          # left edge → pacific
        dfs(r, cols-1, atlantic, heights[r][cols-1])  # right edge → atlantic
    for c in range(cols):
        dfs(0, c, pacific, heights[0][c])          # top edge → pacific
        dfs(rows-1, c, atlantic, heights[rows-1][c])  # bottom edge → atlantic

    return [[r, c] for r in range(rows) for c in range(cols)
            if (r, c) in pacific and (r, c) in atlantic]
```

### Advanced Dijkstra (State + Graph)

When the "shortest path" involves more state than just distance (e.g., "cheapest flight with at most k stops"):

```python
# ─── Cheapest Flights Within K Stops ─────────────────────────────────────────
# Modified Dijkstra/Bellman-Ford: state includes number of stops used.
def find_cheapest_price(n, flights, src, dst, k):
    """k stops = k+1 edges maximum."""
    # Use Bellman-Ford (relax exactly k+1 times)
    dist = [float('inf')] * n
    dist[src] = 0

    for _ in range(k + 1):
        temp = dist[:]   # snapshot: can only use edges from PREVIOUS iteration
        for u, v, price in flights:
            if dist[u] != float('inf') and dist[u] + price < temp[v]:
                temp[v] = dist[u] + price
        dist = temp

    return dist[dst] if dist[dst] != float('inf') else -1

# ─── Network Delay Time (Dijkstra) ────────────────────────────────────────────
def network_delay_time(times, n, k):
    """Time for signal to reach all nodes from k."""
    adj = defaultdict(list)
    for u, v, w in times:
        adj[u].append((v, w))

    dist = {k: 0}
    heap = [(0, k)]

    while heap:
        d, node = heapq.heappop(heap)
        if d > dist.get(node, float('inf')):
            continue
        for nb, w in adj[node]:
            new_d = d + w
            if new_d < dist.get(nb, float('inf')):
                dist[nb] = new_d
                heapq.heappush(heap, (new_d, nb))

    if len(dist) < n:
        return -1
    return max(dist.values())
```

## Part 12 — The BFS vs DFS Decision Table

| Problem Type | Algorithm | Why |
|---|---|---|
| Shortest path, unweighted | **BFS** | Level-by-level = fewest edges |
| Shortest path, weighted ≥ 0 | **Dijkstra** | BFS + priority queue |
| Shortest path, negative edges | **Bellman-Ford** | Handles negatives |
| Shortest path, DAG | **Topo sort + relax** | O(V+E), even with negatives |
| All-pairs shortest path | **Floyd-Warshall** | V³, any edge weights |
| Connectivity, components | **DFS or BFS** | Same complexity |
| Cycle detection, undirected | **DFS + parent** | Natural fit |
| Cycle detection, directed | **DFS + colors** | Track recursion stack |
| Topological order | **Kahn's BFS** or **DFS post** | Both O(V+E) |
| Minimum spanning tree | **Kruskal** (sparse) / **Prim** (dense) | Greedy on edges/nodes |
| Strongly connected components | **Kosaraju** or **Tarjan** | 2-pass or 1-pass DFS |
| Bridges / articulation points | **DFS + low-link** | Track back edges |
| Bipartite check | **BFS 2-color** | Clean and iterative |
| Connected components (incremental) | **Union-Find** | O(α(n)) per query |

## Part 13 — Common Mistakes & How to Avoid Them

<Callout type="warn" title="Mistake 1: Marking visited on dequeue (BFS)">
Always mark visited **when you enqueue**, not when you dequeue. Otherwise the same node enters the queue
multiple times before being processed — ruining distance calculations and potentially causing TLE.
</Callout>

<Callout type="warn" title="Mistake 2: Forgetting to handle disconnected graphs">
Always loop over all nodes and start BFS/DFS from each unvisited one. Many graphs in interview problems
are disconnected. Single-source traversal misses isolated components.

```python
# WRONG: only processes component containing node 0
bfs(adj, 0, n)

# CORRECT: handle all components
for i in range(n):
    if not visited[i]:
        bfs(adj, i, n)
```
</Callout>

<Callout type="warn" title="Mistake 3: Dijkstra with negative edges">
Dijkstra assumes once a node is settled (popped from heap with minimum distance), its distance is final.
Negative edges can create a shorter path later — use Bellman-Ford instead.
</Callout>

<Callout type="warn" title="Mistake 4: Comparing visited nodes instead of roots in Union-Find">
For cycle detection via Union-Find: always use `find(u) == find(v)`, not `parent[u] == parent[v]`.
The parent pointer may point to a mid-tree node, not the root.
</Callout>

<Callout type="warn" title="Mistake 5: Parent check in directed cycle detection">
The parent check (`if nb != parent`) is only for **undirected** graphs. For directed graphs, use the
3-color approach (white/gray/black). Applying parent check to directed graphs silently misses cycles.
</Callout>

<Callout type="warn" title="Mistake 6: Stale entries in Dijkstra's heap">
When you push updated distances into the heap, old (larger distance, same node) entries remain. Always
check `if d > dist[node]: continue` when popping — this skips stale entries efficiently.
</Callout>

## Part 14 — Interview Perspective

<QA q="BFS vs DFS — when does each win?">

**BFS** is the tool when distance or levels matter: shortest path on unweighted graphs, minimum steps,
"how many moves to reach X", anything where you need the closest version of something first. It's also
cleaner for iterative implementation (no recursion limit risk). The queue's FIFO property is what gives
you the "nearest-first" guarantee.

**DFS** wins when you need to explore the full depth of a path: detecting cycles, finding any path (not
shortest), enumerating all paths, computing connected components, topological sort, finding SCCs, bridges,
and articulation points. DFS naturally backtracks — the recursive call stack handles it. For graphs with
10⁵ nodes in Python, convert to iterative DFS to avoid hitting the default recursion limit.

The "wrong choice" penalty: using DFS for shortest path silently gives wrong answers on non-tree graphs
(it doesn't guarantee fewest edges). Using BFS for cycle detection works but is less elegant. For weighted
shortest paths, neither plain BFS nor DFS work — upgrade to Dijkstra.

</QA>

<QA q="How do you detect a cycle, and how does directed vs undirected change the approach?">

**Undirected graph:** DFS with parent tracking. When DFS from u reaches already-visited neighbor v, check
if v is u's parent. If no (it's a different ancestor), you've found a cycle via a back edge. The parent
check prevents the obvious false positive of u seeing the edge it just came from.

**Directed graph:** DFS with 3-color states — white (unvisited), gray (currently on the recursion stack),
black (fully processed). If you reach a gray node, that's a back edge → cycle. If you reach black, it's
a forward/cross edge → no cycle from here. The key difference from undirected: edges are one-way, so "v
is visited" doesn't mean "v is an ancestor" — v could be in a completely different branch (cross edge).

**Union-Find for undirected:** When adding an edge u-v, check if they're already connected. If yes,
this edge closes a cycle. Best for "detect cycle as edges are added incrementally." Can't handle
directed graphs (edges have no direction in standard DSU).

**Topological sort:** If Kahn's algorithm outputs fewer than V nodes (some never reached indegree 0),
the remaining nodes form one or more cycles. This is a clean side-effect of Kahn's.

</QA>

<QA q="Explain Dijkstra's algorithm and why it doesn't work with negative edges.">

Dijkstra is a greedy algorithm that maintains a min-heap of (distance, node) pairs. The invariant: when
a node is popped from the heap with distance d, d is the shortest distance from the source. You then
"relax" all edges from that node — if going through it gives a shorter path to a neighbor, update and
push to heap.

It fails with negative edges because of the invariant: once a node is popped, we assume its distance is
final and never update it again. But with a negative edge, a longer-seeming path through a later node
could swing back via a negative edge and give a shorter overall path. Dijkstra never re-examines settled
nodes, so it misses this.

Fix: use Bellman-Ford — it relaxes all edges V-1 times, allowing the "negative shortcut" to propagate.
Cost: O(VE) instead of Dijkstra's O((V+E) log V). In practice: if all weights are non-negative (maps,
networks, positive costs), use Dijkstra. If any weight could be negative (profit/loss, discounts that
reduce cost), use Bellman-Ford.

</QA>

<QA q="When would you use Union-Find vs BFS/DFS for connectivity?">

**Use BFS/DFS when:** the graph is given all at once and you need to answer connectivity once (or a few
times). One O(V+E) traversal labels all components. Also use when you need the actual path or more than
just "are they connected?".

**Use Union-Find when:** edges arrive over time and you need to answer connectivity queries interspersed
with edge additions ("is A connected to B?" after each "add edge C-D"). DSU maintains components
incrementally at amortized O(α(n)) per operation — re-running BFS per query would cost O(V+E) each.
Also the natural tool for Kruskal's MST.

**Union-Find limitation:** no deletions (can't remove edges), no path retrieval (only yes/no connectivity),
only undirected (standard DSU doesn't track edge direction).

The interview tell: "edges arrive one by one" + "connectivity queries" = Union-Find. "Fixed graph,
path needed" = BFS. "Fixed graph, full exploration" = DFS.

</QA>

<QA q="What is a topological sort and when does it apply?">

A topological sort is a linear ordering of nodes in a **DAG** such that for every directed edge u→v, u
appears before v. It only exists if the graph has no cycles (the "A" in DAG). If a cycle exists, there's
no valid ordering — course A requires B requires A is unsatisfiable.

Real-world applications: build systems (compile A before B), task scheduling (do A before B), package
managers (install dependencies first), spreadsheet formula evaluation (compute dependency cells first),
compiler analysis (evaluate expressions in dependency order).

Two algorithms: Kahn's (BFS, repeatedly removes in-degree-0 nodes — clear cycle detection as a side
effect) and DFS post-order (add each node to result after fully exploring its subtree, then reverse).
Both O(V+E). Prefer Kahn's when you also need cycle detection or "by-level" processing order. Prefer DFS
when you're already doing DFS (e.g., computing finish times for Kosaraju's SCC).

Interview trap: topological sort questions often don't say "topological sort" — they say "course schedule",
"build order", "alien dictionary". The tell is: directed relationships where ordering matters.

</QA>

<QA q="Design a system to find shortest routes between any two cities — which graph algorithm would you use?">

This is Floyd-Warshall vs Dijkstra × V times vs Johnson's algorithm, depending on scale.

**Small network (≤ 500 cities):** Floyd-Warshall. Precompute all-pairs in O(V³) — for 500 cities that's
125 million operations, fast enough. O(V²) space to store all distances. Any subsequent query is O(1)
lookup. Handles negative edges (if we're modeling things like toll credits).

**Large sparse network (10,000+ cities, sparse connections like highways):** Run Dijkstra from each source
— O(V × (V+E) log V). For a road network where E ≈ 6V (each city connects to ~6 roads), this is far
cheaper than Floyd's V³. Cache frequently queried pairs.

**With preprocessing time (GPS/maps):** Bidirectional Dijkstra (search simultaneously from source and
destination, meet in the middle — dramatically faster in practice), A* with geographic heuristics (known
lower bound = Euclidean distance), or Contraction Hierarchies (real-time GPS standard — preprocess once,
queries in microseconds).

**Production Google Maps answer:** A*, bidirectional, with contraction hierarchies for the static road
network and Dijkstra layers for real-time traffic. The key insight: graph algorithms research didn't stop
at Dijkstra.

</QA>

## Part 15 — Complexity Cheat Sheet

| Algorithm | Time | Space | Notes |
|---|---|---|---|
| BFS | O(V + E) | O(V) | Shortest path on unweighted |
| DFS | O(V + E) | O(V) | Stack depth = path length |
| Dijkstra (binary heap) | O((V+E) log V) | O(V) | Non-negative weights |
| Dijkstra (Fibonacci heap) | O(E + V log V) | O(V) | Theoretical; rarely implemented |
| Bellman-Ford | O(VE) | O(V) | Handles negative edges |
| Floyd-Warshall | O(V³) | O(V²) | All-pairs |
| Topological Sort | O(V + E) | O(V) | DAG only |
| Kruskal's MST | O(E log E) | O(V) | Sort edges + Union-Find |
| Prim's MST | O((V+E) log V) | O(V) | With binary heap |
| Kosaraju's SCC | O(V + E) | O(V) | Two-pass DFS |
| Tarjan's SCC | O(V + E) | O(V) | Single-pass DFS |
| Bridges / APs | O(V + E) | O(V) | DFS + low-link |
| Bipartite check | O(V + E) | O(V) | BFS 2-coloring |
| Hamiltonian Path | O(n!) / O(2ⁿ × n) | O(n) | NP-hard; bitmask DP for n≤20 |
| Eulerian Circuit | O(V + E) | O(V) | Hierholzer's algorithm |
